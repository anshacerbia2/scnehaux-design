One line, drawn and verified.

How the Scnehaux UI documentation looks and moves. The docs are drawn as one continuous technical line, and every part of the reading is verified: the section you are in, the sections you have read, the labels you point at.

See it live Scroll behaviour

This book covers

The chrome of the docs site: lines, layout, the nav, section bars, cells, type voices, colour roles, motion and the ruler scrollbar. It is the reference for ui-platform-docs.

It does not cover

Product components and token values. Those belong to ui-platform (@scnx/system) and the Scnehaux UI brand book (design-system/README.md). This book uses them; it never redefines them.

02 Principles
Count
six

Six rules the whole site keeps.

01

One line, never a box in a box

The page is one drawing. Areas are cells that share their dividers. Nothing is framed inside another frame.

02

Square

No radius, in the chrome or in a component: square is the system's structure. Only a round that means something stays round (a radio, a switch, a status dot). Corners are where lines meet, and a strong cross marks every join of a rule and a column.

03

Blue means here

Scnx Blue marks only the current place, focus, selection, links and checks. It is never decoration and never a button fill.

04

Two voices

Inter speaks the content. A tracked, upper-case mono speaks the instrument: bars, labels, facts, readouts, buttons.

05

Verify, don't decorate

Motion proves something: a section read is checked, a label pointed at is re-verified from hash characters. Nothing moves only to move.

06

Motion answers the reader

Movement follows the scroll, the pointer or the keys. It plays back when scrolled back, and stops under reduced motion.

Blue has two roles. Blue text (a link, the current section number, the readout) is primary.text.*, never the fill. Blue lines and fills (the now line, the here mark, a check) are primary.surface.solid. Derived values (edge, cross, line, faint, glass) are mixes of tokens, declared on every theme root so a dark island on a light page resolves its own. They are expression-local (--sq-*), never new tokens. Status colours (success, warning, danger) come only through ui-platform components such as Badge.
RoleWhereNeedsDarkLight
Measured live, in this browser, from the tokens this page loads: each colour is painted over its ground in a light and a dark island and read back, so mixes and opacity count as drawn. Needs is WCAG 2.2: 4.5:1 for text (1.4.3), 3:1 for a control's boundary and for a graphic that carries meaning (1.4.11). Line and faint carry no meaning on their own, so they have no minimum and are never used for text.

Specimen rule. Where a page shows a component, in the chrome or as a specimen (a component page's stage, a do and don't example), it renders with the system's tokens, as it ships. The structure is square in every theme (the industrial structure), and a theme switch on a stage changes only colours, so a specimen and the chrome always agree. Until @scnx/system ships that structure, square.css carries a bridge: it sets the radius ladder (not pill) and the on-page materials through the documented tokens, in the consumer's overrides layer. Delete the bridge when the package ships. Nothing selects .scnx-*.

Never animate a component specimen. Never loop motion that the reader did not cause, except the receipt tape, which pauses on hover and focus. Under reduced motion nothing glides, rises or shuffles; titles still follow the scroll, because they are positions.

11 Adopting it in ui-platform-docs
Owner
scnehaux-design

Take the values from ui-platform. Build the chrome in the docs.

From ui-platform

Tokens and components

Colour roles in both modes, type families, spacing, motion tokens, and every component the pages show (Button, Badge, Segmented, Switch, Kbd, Code). Nothing is copied: the docs depend on @scnx/system.

In ui-platform-docs

The chrome

The line system, nav strip, section bars, cells, facts, lead, calls to action, the ruler and its titles, reveal, glide and verify. The reference implementation is square.css and square.js in this folder.

Here, in scnehaux-design

This book

Rules, values and examples. A change to the look lands here first, by pull request, and the docs follow. The docs do not write their own brand rules.

Order. First, ui-platform ships the industrial structure (square, the same in every theme; the theme default becomes industrial), wave 1 (Kbd, Segmented control), and the docs serve IBM Plex Mono from their own origin (font-src 'self'; the files and licence are in design-system/fonts/). Then port square.css and square.js on top of @scnx/system's tokens, without the bridge once the structure has shipped, and give TableOfContents its controlled activeId. Last, migrate the pages to the sheet structure (bars, cells, facts). The behaviour to match is in SCROLL.md.
